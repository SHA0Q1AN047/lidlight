# Lidlight 1.9.5

CPU temperature now follows a fixed sensor instead of switching to whichever thermal channel is hottest at each sample.

- Preserve model-specific sensor priority and keep a valid selected sensor stable.
- Keep a working fallback sensor when an earlier source returns; replace it only after three consecutive unavailable or invalid readings. Brief failures show unavailable instead of switching immediately or holding old values.
- Apply stable selection to both SMC and CPU-named HID services.
- Show the current sensor identity in Performance; rename the home metric to CPU temp.

Temperature can still change with real CPU activity. Readings are not artificially smoothed or held after failure. Live checks are limited to M2 Pro; other model limitations from 1.9.4 still apply.

The app is ad-hoc signed; the installer is unsigned and not Apple-notarized.
