# Clear glass dashboard

Replace NSPopover with a transparent borderless nonactivating NSPanel so the window shell does not impose the system popover backdrop. The panel remains anchored to the menu-bar button, accepts keyboard focus, clamps position to the current display, and removes temporary mouse/application/display observers when hidden. Embedded menus/popovers and the status-item toggle are excluded from outside-click dismissal. Escape, application changes and screen changes hide it; sampling still uses the existing visible-state gate.

Use one behind-window visual effect at 0.38 SwiftUI opacity. Opacity is applied by SwiftUI rather than changing the represented NSView's alpha, which SwiftUI can manage itself. Content surfaces use a 0.012–0.055 white highlight plus a fine reflective border rather than another glass/blur layer. Native clear Liquid Glass controls remain on macOS 26. Older systems retain their standard material controls. Reduce Transparency and opaque layout previews retain solid fills. No power/sensor/fan behavior changes.

Validation:
- Universal arm64/x86_64 build passed, macOS 12 deployment target unchanged.
- Release Swift suites passed, including fixed CPU-source regressions and new panel geometry/keyboard/Escape/repeated-close checks.
- Native fixture app previews inspected in light and dark appearances. Actual anchored panel opened; embedded power-mode popover opened and selected without closing the parent; Preferences navigation and event-name typing worked; Escape dismissed the panel.
- Isolated window screenshots use sample quota/performance data and may flatten the desktop backdrop; they validate layout and interaction, not the exact transparency/color on every wallpaper. No physical old-macOS or multi-monitor interaction validation is claimed; negative-coordinate placement is covered by deterministic geometry checks.
